Configure how Sponsor Gated Support gates issues, greets <Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsors</Terminology>, and handles non-<Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsors</Terminology> through 11 repository-level inputs.

## Tokens

Both tokens live under the **Secrets** tab (Settings > Secrets and variables > Actions > Secrets tab) so their values stay masked in workflow logs.

### `GITHUB_PERSONAL_ACCESS_TOKEN`

A classic <Terminology title="classic token used only to read sponsor data" to="/docs/reference/terminology#personal-access-token-pat">personal access token</Terminology> used to query the GitHub Sponsors API. You can generate one from the [Personal Access Tokens (Classic)](https://github.com/settings/tokens) page.

The token needs two scopes:

- `read:org` — reads organization membership when `IS_ORGANIZATION` is `true`.
- `read:user` — reads <Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsor</Terminology> relationships for personal accounts.

The workflow reads this value from `${{ secrets.PERSONAL_ACCESS_TOKEN }}`.

### `GITHUB_WORKFLOW_TOKEN`

The automatic token GitHub provides on every workflow run. You don't need to create this one — passing `${{ secrets.GITHUB_TOKEN }}` is all it takes.

This token handles issue moderation: posting comments, closing issues, deleting unauthorized comments, and locking threads.

## Issue Gating

These variables control which issues the action monitors and how it moderates them. You can find them under the **Variables** tab (Settings > Secrets and variables > Actions > Variables tab).

### `ISSUE_LABELS`

A comma-delimited list of label names. The action only gates issues that carry at least one of these labels.

```text title="Example values"
support
support,premium support
```

Defaults to `support`.

### `ISSUE_LIMIT_COMMENTER`

When set to `true`, only the issue opener, organization members, repository owners, contributors, and collaborators can comment. Unauthorized comments are automatically deleted.

Defaults to `true`.

### `ISSUE_LOCK_ON_CLOSE`

When set to `true`, the action locks an issue's conversation as soon as it moves to a closed state. This prevents further comments on resolved threads.

Defaults to `true`.

## Messages

Both variables accept plain text or GitHub-flavored Markdown. You can find them under the **Variables** tab.

### `ISSUE_MESSAGE_NOT_SPONSOR`

The comment posted when a non-sponsoring user opens a gated issue. The issue is closed immediately after this message appears.

Default value:

```text title="Default message"
Apologies! Only sponsoring users are allowed to open issues. Please sponsor the owner of this repository, then try again.
```

### `ISSUE_MESSAGE_WELCOME`

The comment posted when a verified <Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsor</Terminology> opens a gated issue. The issue stays open for the team to triage.

Default value:

```text title="Default message"
Thank you for your support! We appreciate your sponsorship and are here to help. We will review your issue and get back to you as soon as possible.
```

You can personalize these messages with your project's branding, links to your <Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsor</Terminology> page, or support-specific instructions.

## Sponsorship

These variables define who qualifies as a <Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsor</Terminology>. You can find them under the **Variables** tab.

### `IS_ORGANIZATION`

When set to `true`, the action queries the organization's <Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsor</Terminology> list instead of the individual user's. You'll want to enable this for any repository owned by a GitHub organization.

Defaults to `false`.

### `SPONSOR_ACTIVE_ONLY`

When set to `true`, only users with an active sponsorship pass the gate. Past <Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsors</Terminology> whose sponsorship has ended are treated the same as non-<Terminology title="a user or org sponsoring you via GitHub Sponsors" to="/docs/reference/terminology#sponsor">sponsors</Terminology>.

Defaults to `true`.

### `SPONSOR_MINIMUM`

The minimum sponsorship amount (in cents) a user needs to pass the gate. A value of `0` means any sponsorship amount qualifies.

```text title="Example values"
0       # Any amount
50      # $0.50 USD
1000    # $10.00 USD
```

Defaults to `0`.

## Exempt File

### `SPONSOR_EXEMPT_FILE_LOCATION`

Path to a newline-delimited text file listing GitHub usernames that bypass the sponsorship check. The path is relative to the repository root, not the workflow directory.

Defaults to `./SPONSOR_EXEMPT`.

The file uses one username per line with no `@` prefix:

```text title="SPONSOR_EXEMPT"
octocat
mona
hubot
```

Blank lines and leading or trailing whitespace are ignored. You can use this file to grant access to beta testers, maintainers, or community members who contribute in non-monetary ways.
